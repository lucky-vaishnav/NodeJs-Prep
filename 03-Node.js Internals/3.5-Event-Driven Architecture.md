## 1. What is event-driven architecture?

Event-driven architecture (EDA) is a design approach in which components react to events rather than requiring every component to directly call every other component.

An event represents something that has happened, such as:

- A payment completed.
- A user registered.
- A file finished processing.
- A parking reservation was cancelled.

A component emits or publishes an event, and one or more interested components react to it.

## 2. Is event-driven architecture the same as Node.js's Event Loop?

No. This distinction is important in senior interviews.

- Event-driven architecture is a software design pattern for communication and coordination between components.
- Node.js Event Loop is a runtime mechanism that coordinates the processing of eligible callbacks and other work.

They share the idea of reacting to events, but they operate at different levels.

Node.js's built-in `EventEmitter` can implement event-driven behavior inside one process. A message broker such as Kafka can support event-driven communication across separate services.

Neither requires the other: you can design an event-driven system in another runtime, and a Node.js application can use a straightforward request-response architecture.
